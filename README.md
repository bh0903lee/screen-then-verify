# Screen, Then Verify — code and results

Code and per-run results for the manuscript
**"Oracle-Efficient Multi-Metric Network Design via Metric Sketches and Selective Verification"**
(B. Lee, S. Kang, I. Hong; submitted to IEEE Transactions on Network Science and Engineering).

The repository contains the code and the exact commands of the editing experiments and of the generative baselines, and
the result tables behind every reported number. For the GNN-probe and downstream-property analyses of the four-network
pilot (Supplementary S4) it provides the graph-level observation tables, from which the reported statistics can be
recomputed, but not the code that measured them. It contains no table- or figure-rendering code: each number in the
paper is listed in `results/claims.csv` together with the result files and the computation that give it, so it can be
recomputed with any data tool.

## Layout

| Path | Content |
|---|---|
| `stv/` | library: exact metric oracle and edit environment (`graph_env.py`), edit operators and proposals (`operators.py`), the metric sketch (`sketch.py`), synthetic targets (`targets.py`, `ws_targets.py`), real networks (`real_networks.py`), learned predictors (`predictors.py`, `edit_head.py`), selector extensions (`extensions.py`), warm-start construction (`warmstart/`) |
| `experiments/` | command-line entry points (below) |
| `baselines/generative/` | wrappers around two public graph generators (not included; see "Generative baselines") |
| `jobs/` | `<experiment>.txt`: the exact command line of every run behind the paper, one per line |
| `data/` | `networks.csv` (28 public networks: source URL, SHA-256, citation), `network_clusters.csv`, `download_networks.py` |
| `results/runs/`, `results/start_cache/` | per-run result tables and shared start graphs: **in the separate data archive** (see "Results") |
| `results/*_sketch_acc_metrics.csv`, `results/models/conformal/` | calibration outputs that later runs read (spectral slope kappa, conformal thresholds) |
| `results/claims.csv` | every reported number: paper location, value, result files, computation |

## Installation

Python 3.11. CPU only for all editing runs; the graph neural rankers train faster on a GPU.

```
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export OMP_NUM_THREADS=1        # every run of the paper used one thread
```

Warm-start construction uses `python-louvain` for one community step when it is installed and networkx greedy
modularity otherwise. Runs that read `results/start_cache/` do not depend on this. Of the runs that build their own
starts, those in `jobs/real_networks*.txt`, `size_ladder.txt`, `ranking_large_N.txt`, `learner_scaling.txt`,
`required_ranking_quality.txt`, `adaptive_verification.txt` and `generic_surrogates.txt` were made without
`python-louvain`, all others with `python-louvain==0.16` installed.

## Data

The synthetic targets are generated by the code. The 28 public networks (24 benchmark networks and 4 development
networks) are **not redistributed**; download them unchanged from the Netzschleuder repository and check their hashes:

```
python data/download_networks.py
```

Each network keeps its own license and citation (`data/networks.csv`, column `citation`, and the network's page on the
repository). Start graphs derived from these networks are not included either; the real-network runs rebuild them from
the downloaded files.

## Entry points

| Script | Purpose |
|---|---|
| `experiments/run_experiment.py` | one run = (operator, seed, selectors) on the evaluation targets of a seed; writes one CSV per selector |
| `experiments/calibrate_sketch.py` | per-candidate sketch accuracy on training-sampler seeds; `--summary` fits the spectral slope kappa |
| `experiments/candidate_pool.py` | fixed candidate pools labelled by the oracle (ranking analysis; training data of the predictors) |
| `experiments/train_direct_predictor.py`, `train_gnn_predictor.py`, `train_ranker.py` | learned predictors and rankers |
| `experiments/conformal_thresholds.py` | split-conformal thresholds for adaptive verification |
| `experiments/action_gap.py`, `label_saturation.py`, `value_replay.py` | diagnostics of the value learners |

Outputs go to `results/run_<tag>/<operator>_seed<seed>_<selector>.csv`.

**Operators** (`--arms`): `S_swap` (degree-preserving swap), `S_swap3` (3-swap), `S_rewire`, `S_adddel` (add/delete),
`S_jdm` (joint-degree swap); a `t` prefix (`S_tswap`, ...) is the typed proposal of the same operator, an `o` prefix the
oracle screen; `a+b` mixes operators, `a@m+b@n` fixes the candidate share, `L1`–`L4` is the operator ladder.

**Selectors** (`--policies`): `random`; `greedy` (oracle-scores `--greedy-k` candidates, applies the best); `beam`;
`sketch` (sketch top-1, no verification); `sketch_k8` (Sketch-V8: verify the sketch's top 8); `beam_sketch` (the
composed selector Sketch-Beam, with `--K 64 --sketch-q-refresh 5`); `value`, `value_rel`, `value_rel_res`, `value_sketch`,
`value_td`, `value_mc` (value learners); `pred*`, `gpred*`, `nnpred*`, `gbp*` (learned predictors; `_k8` = top-8
verified); `uct`; `sa_free`, `hill`, `hill_free`, `mcmcf*` (chains); `rho*`, `rhov*` (synthetic rankers of given
quality); `skq<q>` (Sketch with q verifications); `cv<alpha>` (adaptive verification); `olr_k8`, `olrm_k8`, `ogb_k8`,
`mf_k8`, `bsk_k8`, `lsk_k8` (generic online surrogates).

## Reproducing the paper

Each file in `jobs/` holds one command per line. Lines inside a file are independent except where a step below says
otherwise; run the files in this order, since later steps read what earlier ones write:

1. `jobs/sketch_calibration.txt` — calibration runs, then (at the end of the file) their `--summary` lines, which write
   the kappa files `results/run_sketch_calibration__<variant>_sketch_acc_metrics.csv`, and the conformal-threshold line.
   The kappa and threshold files of the paper are already included, so this step can be skipped.
2. `jobs/training_pools.txt`, `jobs/candidate_pool.txt` — oracle-labelled candidate pools.
3. `jobs/model_training.txt` — predictors and rankers, in file order (direct predictors write `results/models/boosting`
   and the held-out-family folders, which the GNN predictor lines read; ranker lines come last).
4. All other files except `generative.txt`, in any order. Within `operators.txt` and `value_learners.txt`, run the
   `value_replay.py` lines only after the runs that train the value networks they read (they come earlier in the file).
5. `jobs/generative.txt` — generative baselines, in file order (see "Generative baselines").

The synthetic runs read their start graphs and targets from `results/start_cache/` (`--warm-cache`, `--target-cache`).
Start construction is not deterministic across processes, so the cache is what makes paired comparisons start from
identical graphs; with the cache, a run reproduces the reported per-target results up to timing columns.
One run (one operator, one seed) takes minutes to hours on one core.

## Results

The result data are distributed as a separate archive (`screen-then-verify-data.zip`, submitted with the manuscript as
supplementary material). Its files sit under a top folder `screen-then-verify/`, so unpack it in the directory that
contains the repository folder, for example from the repository root:

```
unzip screen-then-verify-data.zip -d ..
ls results/runs results/start_cache      # both must exist
```

If your copy of the repository has another folder name, unpack the archive anywhere and move the folders under its
`screen-then-verify/results/` into the repository's `results/`.

It adds `results/runs/` and `results/start_cache/`:

- `results/runs/<experiment>/<variant>.csv.gz`: the per-run files of one experiment arm, concatenated (one row per target
  and band; per candidate for `sketch_accuracy` and `ranking_large_N`; per state for `candidate_pool`);
- `results/runs/generative/`: best-of-k evaluations of the generative baselines (per target);
- `results/runs/model_validation/`: validation curves of every trained predictor and ranker (model selection);
- `results/runs/learner_analysis/`: per-state values behind the distillation and ranker-mechanism analyses;
- `results/runs/real_pilot_probes/`: graph-level observations of the four-network pilot (Supplementary S4): GCN and MLP
  test accuracy per reached graph of the (Q, lambda2) target grids, and downstream properties of the own-degree-start
  graphs and of the null ensembles they are compared with (numbers only; no graph is included);
- `results/start_cache/<name>/`: start graphs and targets of the synthetic runs.

Trained models, candidate pools used as training data and value-network checkpoints are not distributed; `jobs/`
regenerates them. Common columns of the run tables:

| Column | Meaning |
|---|---|
| `source_file` | the per-run file the row came from (`<operator>_seed<seed>_<selector>`) |
| `run` | the run name (`<experiment>__<variant>`, the `--tag` of the command in `jobs/`) |
| `seed`, `arm`, `policy`, `target`, `family`, `band` | seed, operator, selector, evaluation target, target family, tolerance band (`u0.4` = u = 0.4) |
| `sat` | 1 if the target was satisfied within the horizon, else 0 (empty where the selector does not run that band, e.g. beam-type selectors outside `--beam-bands`) |
| `oracle_calls`, `oracle_to_hit` | candidate-ranking oracle calls in total / until the first satisfying state |
| `oracle_total`, `oracle_total_to_hit` | all metric evaluations (including verification and state feedback) in total / to the first hit |
| `t_wall`, `t_to_hit`, `t_setup` | search-phase seconds, seconds to the first hit, setup seconds |
| `sketch_calls`, `sketch_cand`, `sketch_time` | sketch states, sketched candidates, sketch seconds |
| `sketch_lam_scale` | the spectral slope kappa used |
| `start_hash` | hash of the start graph (equal across selectors of a paired comparison) |

Failed targets count with their full consumption. Every contrast in the paper is a seed-level paired difference
(satisfaction averaged over targets, and over operators within a seed where stated) with a percentile bootstrap over
seeds (10^4 resamples) unless `results/claims.csv` states otherwise.

`results/claims.csv` lists, for every number in the paper, its location (section, table or figure of the submitted
manuscript), the value as printed, the result files, and how it is computed.

## Generative baselines

`baselines/generative/` wraps two public generators, which are **not included**:

- DiGress, https://github.com/cvignac/DiGress, commit `3106266` (guidance branch), cloned into `external/DiGress_guidance`.
  Its k-cycle feature code asserts non-negative cycle counts; with fp32 these counts can be slightly negative on dense
  noisy graphs. We replaced the four assertions in `KNodeCycles.k_cycles` (`src/diffusion/extra_features.py`) by clamping
  the counts at zero.
- Neural Graph Generator, https://github.com/iakovosevdaimon/Neural-Graph-Generator, commit `7073338`, cloned into
  `external/NGG`.

Each keeps its own license and needs its own environment (for example PyTorch Geometric for the Neural Graph
Generator; see each repository). `jobs/generative.txt` lists the commands of the reported runs in order: training
data, the discrete-diffusion denoiser and guidance regressor, the guidance-strength selection on validation seeds
20–22, best-of-k sampling on the evaluation targets (k = 256) and scoring; then the same for the latent-diffusion
model. Generator training does not fix the random seed, so retrained checkpoints
reproduce the reported generator results statistically, not bit for bit.
